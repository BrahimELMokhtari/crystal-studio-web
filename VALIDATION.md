# Version 1.1 validation

Checked on 3 October 2026 with Python 3.14.7, Node.js 24.21.0 and installed Google Chrome on Windows. Browser checks use the real WebGL viewer and the real local FastAPI service.

- **65 Python tests passed:** CIF/VESTA symmetry, skew cells, occupancies, input bounds, periodic image shifts, supercell rebuilding, API errors, concurrency, request limits, CORS, manually defined structures and safe element-data fallbacks through element 118. There are 49 existing upstream dependency deprecation warnings.
- **35 JavaScript tests passed:** manual triclinic geometry and text parsing, all 118 element symbols, malformed and coincident sites, direct manual connections, contact deduplication, supercell endpoint remapping, legacy and current project validation, physical export dimensions, PNG resolution metadata, raster alignment and bounded alpha scans.
- **Existing browser integration passed:** actual WebGL; layouts at 320, 375, 768 and 1,440 pixels; keyboard navigation; atom selection and measurements; periodic contacts; safe project save/load; CIF import; retention after invalid input; contact-cutoff rebuilding; supercell calculation; and cancellation of older work.
- **New browser integration passed:** a square 3D canvas at all four screen sizes; offline manual cell creation with skew lattice vectors and occupancy; duplicate-site error retention; selecting and connecting two atoms; project persistence of connections; rejected null connections without losing the current structure; real Python contact calculations; and retained manual connections when expanding a supercell.
- **Export pixels checked independently:** transparent 8 cm square PNGs at 300 and 600 DPI have the requested horizontal legend-to-atom separation after orbit and zoom. The spacing is round(DPI / 2.54) completely empty pixel columns between visible legend ink and the nearest rendered atom edge. One centimetre is quantized to the nearest pixel, with at most half a pixel of physical rounding error. Cell edges and axes can occupy part of this gap.
- **Higher resolution checked:** a 5 cm square PNG at 2,400 DPI exports at 4,724 x 4,724 pixels, exceeding the previous 4,096-pixel side limit. PNG physical-resolution metadata is checked. The default is now 8 x 8 cm at 1,200 DPI (3,780 x 3,780 pixels). Limits are 8,192 pixels per side, 32 million total pixels, and the device's actual WebGL limits.
- **Background and PDF checked:** transparent PNG corners and empty image areas have alpha zero; the white-background option produces an entirely opaque image. An 8 cm square PDF has the expected 226.772-point square page and retains the PNG alpha mask. Legend-off export also works. Exports restore the interactive camera, viewer dimensions and background exactly.
- **Additional WebGL export cases passed:** 16 captures cover all four representations and four camera directions, including unit-cell edges, axis labels, periodic images and selected-atom outlines. Each keeps the legend clear of the scene and maintains the requested spacing. Bonds-only views use the visible geometry as their spacing reference. Legend-off and rejected-export camera restoration also pass.
- **Current design checked visually:** actual transparent exported PNG, desktop layout, mobile layout and the manual-definition dialog were inspected. The legend uses shaded sphere artwork and simple element symbols in one fixed upper-left vertical column. Larger element sets shrink uniformly to stay inside the figure.
- **Delayed project-read race checked:** a newer manual structure or newer project survives an older file read; a stale read error cannot replace the latest status. All four deferred-read cases pass.
- **Production build and path checked:** the built app, hashed assets, WebGL and dynamically loaded PDF export work under `/crystal-studio-web/`, matching GitHub Pages repository hosting. Vite reports its existing large Three.js bundle warning; the build succeeds.

No uncaught browser script errors occurred. The bundled structures and test inputs are synthetic demonstrations and regression cases. Manual entry requires the full unit-cell contents; it does not infer symmetry operations. Automatic contacts use covalent-radius cutoffs and should be reviewed for the structure's chemistry. Manual connections join the exact displayed positions selected by the user; they are retained where endpoints remain in a resized supercell, without automatically copying them into new tiles.

The public project uses [GitHub Pages](https://brahimelmokhtari.github.io/crystal-studio-web/), the [GitHub source repository](https://github.com/BrahimELMokhtari/crystal-studio-web), and a Python API on [Render](https://crystal-studio-api.onrender.com/health). The Render service is on the Free plan in Frankfurt; its first request after inactivity can take longer while it starts. Free hosting was verified for the preceding live release. Version 1.1 local and production-path checks are recorded above; deployment is verified separately after publishing.

Reproduce the checks with the commands in README.md. `tests/improvements.py` accepts `--url` and `--api` to check a deployed site. For the GitHub Pages path, build with `VITE_BASE_PATH=/crystal-studio-web/`, preview on port 5175, then run `node tests/pages.mjs`; `PAGES_URL` can override that preview address. The standard browser regression accepts `CRYSTAL_URL` and `CRYSTAL_API_URL`.

After building `frontend/dist`, run `python scripts/package.py` from this folder to create a verified source archive. It includes the production frontend and excludes dependency folders, environments, local uploads and test artifacts.
